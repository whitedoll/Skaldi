# 내부 동작

왜 이렇게 만들었는지에 대한 기록이다. 쓰는 방법은 [README](../README.md)에 있다.

## 처리 순서

1. **탐지** `ogkalu/comic-text-and-bubble-detector` (RT-DETR-v2) — 말풍선 / 말풍선 안 글자 / 말풍선 밖 글자
2. **분할** `mayocream/koharu-layout-rfdetr-seg-2xl-1152` — 말풍선·글자·효과음 윤곽 (장당 약 2.4초). 손글씨 효과음 판정과 지우기 범위 제한에 쓴다
3. **OCR** `genshiai-daichi/baberu-ocr` (기본) 또는 LLM 비전(`--ocr llm`). 이어서 교차검증
4. **순서·분류** 비전 모델(Ollama)이 번호 붙은 페이지를 보고 읽기 순서와 말풍선 밖 글자의 종류(대사/나레이션/라벨/효과음)를 판정
5. **글꼴·굵기 측정** 원문 획을 픽셀로 재서 계열(고딕/명조/손글씨)·굵기·획 색을 정한다
6. **번역** 페이지 단위로 텍스트 모델(Ollama)에 한 번에. 용어집 병합. 거부·순화 감지 시 재시도 모델로 자동 전환
7. **지우기** 글자 획 픽셀만 찾아 주변 배경색으로 메움. 그림 위 글자는 LaMa 인페인팅
8. **렌더링** `pillow`(기본) / `anytext` / `qwen`(ComfyUI) / `both`

## OCR 헛읽기 거르기

Baberu는 못 읽는 글자에서도 문법이 멀쩡한 가짜 문장을 지어낸다(`それでも、これからは、`). 확신도(토큰 확률 평균)가 실측 0.45~0.80으로 낮게 나오므로 이것을 1차 신호로 쓴다(정상 판독 0.78~1.00).

- **말풍선 밖 글자는 전부** 비전 모델로 다시 읽어 비교한다. 검은 톤 위 흰 외곽선 글씨를 Baberu가 못 읽는다. 일치도 실측(44영역): 정상 인쇄체 0.25~1.0, 환각 0~0.06.
- **말풍선 안 글자는** 확신도가 `min_confidence`(0.8) 미만일 때, 또는 **글자가 유난히 클 때** 다시 읽는다. 큰 손글씨 신음(`お゛ご゛お゛っ`)에서 Baberu가 `そういうことで` 를 확신도 0.81로 지어냈기 때문이다. 크기는 인식한 글자 수가 아니라 세로 열 폭(픽셀)으로 재고, 페이지 중앙값의 `oversized_ratio`(1.4)배 이상이면 대상이다. 실측: 보통 대사 0.7~1.2, 손글씨 신음 1.5~3.0.
- 비전 판독도 믿을 수 있을 때만 쓴다. 여백을 달리해 두 번 읽어 `vision_consistency`(0.8) 이상 맞아야 채택한다. 지어낸 판독은 매번 달라진다(`おはようございます` ↔ `んぼまぼま`).
- 일치도를 잴 때 `っ`, `ー`, 작은 글자는 뺀다. 이것들은 어느 판독에나 흔해서 가짜끼리도 겹친다(`はははっっ` ↔ `ぼっぼっ` 이 0.5로 나왔다).
- 두 판독이 어긋나는데 한쪽이 발성 글자뿐이면 손글씨 신음으로 보고 원본을 둔다. 탁점 모음(`お゛`)은 비전 모델이 `ボ`·`ポ`·`ご` 로 읽는다.
- Baberu의 버릇 두 가지를 되돌린다: 세로 말줄임표를 쌍점으로(`：` → `…`), `♀` 를 전각 숫자로(`９` → `♀`).

## 효과음·신음 원본 유지

번역하지 않고 원본 그림을 남기는 경우다.

- **효과음(sfx)**: 같은 글자 반복(`おおおお`)과 말풍선 밖 짧은 가타카나(`ゴキュッ`)는 규칙으로 확정. 말풍선 안 글자는 분할 모델·비전 모델·번역 모델 중 둘 이상이 효과음이라고 해야 인정한다(웃음 `クスクス` 가 효과음으로 빠지지 않게). 같은 말풍선에 확정 효과음이 있으면 함께 잡힌 짧은 조각도 효과음으로 본다.
- **신음(filler)**: 번역해도 음역밖에 안 되는 발성(`おおお`, `んほっ♥`, `はぁはぁ`). 번역 모델이 문맥상 뜻이 없다고 보고(`note: filler`, 실제로는 `sfx` 라고 답하는 경우가 더 많다) **동시에** 원문이 모음·`ん`·`は`행·탁점 모음 글자로만 되어 있을 때만 적용한다. 웃음(`ふふ`), 짧은 대답(`はい`, `うん`), 의문(`え！？`)은 규칙에서 막아 항상 번역한다.
- **불명확(needs_review)**: 번역 모델이 뜻을 못 잡았거나 두 OCR이 어긋난 글자. 원본을 두고 JSON에 표시한다.

## 지우기

말풍선 박스 전체를 크롭해 글자 획 픽셀만 찾는다. 배경 밝기는 글자 상자 안쪽 가장자리 띠에서 재고, 그 띠의 밝기가 두 가지 이상 섞이면(사선·들쭉날쭉한 말풍선) 국소 배경과 비교한 뒤 LaMa로 메운다. 글자에 인접한 배경 연결 영역 안의 글자만 주변 배경색(정규화 블러 추정)으로 메우므로, 어두운 말풍선 테두리는 배경 영역에 끼지 못해 절대 지워지지 않고 회색 배경·톤도 남는다. 그림 위 글자는 LaMa 인페인팅.

분할 모델을 켜면(`layout.erase`) 지울 픽셀을 모델이 찾은 글자 근처로 줄이고, 모델이 글자라고 한 곳은 반드시 지운다. 반투명 말풍선에 비치는 그림 선까지 지우던 문제를 막는다.

`erase.widen_bubbles`(기본 `false`)는 좁은 말풍선을 가로로 넓혀 테두리를 다시 그린다. 원본 말풍선을 건드리는 것보다 글자가 곡선에 조금 걸치는 편이 낫다고 보아 기본은 꺼 둔다. 켜면: 지금 상자에 기준 크기의 `widen_min_font_ratio` 이상으로 `widen_max_lines` 줄 안에 들어가는 말풍선은 손대지 않고, 나머지만 `widen_max_ratio` 까지 넓힌다. 확대는 마스크가 아니라 **윤곽선(점 목록)** 에 적용한다 — 마스크를 픽셀째 늘리면 계단이 남아 말풍선이 각져 보이고, 흐림·이진화로 계단을 지우면 가는 부분이 사라져 테두리가 두 겹이 된다. 뿔이 뻗은 폭발형 말풍선은 넓히지 않는다(뿔이 뭉개진다).

## 글자 자리 잡기

- **말풍선 안쪽을 픽셀에서 잰다.** 탐지기가 준 말풍선 박스는 꼬리·뿔까지 감싼 바깥 상자라, 그 중심에 글자를 놓으면 본체에서 치우친다(폭발형 말풍선에서 40px 넘게 어긋난 예). ① 내부 마스크에서 폭이 최대의 40%도 안 되는 가장자리 줄을 잘라 **본체**를 구하고, ② 그 안에서 세로 중앙을 유지한 채 **내접 사각형**을 찾아 `body_box` 에 넣는다. 둘째 단계가 필요한 이유는 말풍선이 둥근데 글자 상자는 사각형이어서다. 폭 84%·높이 84% 상자는 타원 조건 `(w/W)² + (h/H)² ≤ 1` 을 크게 어겨(1.41) 첫 줄과 마지막 줄 양 끝이 말풍선을 뚫고 나간다. 고를 때는 넓이가 아니라 '두 변 중 더 많이 깎인 쪽'을 최대화한다 — 넓이로 고르면 납작한 말풍선에서 높이를 절반까지 깎는다. 띠의 좌우 경계는 최댓값·최솟값이 아니라 **85/15 퍼센타일**로 잡는다(말풍선에 인물이 걸쳐 한 줄만 파여도 상자 전체가 좁아지던 문제).
- 잰 본체가 **원문 글자 상자를 80%도 덮지 못하면 글자 상자까지 넓힌다.** 그림 위에 얹힌 반투명 말풍선은 색 채우기가 망점에 막혀 아래 절반만 잡히는데, 원문 글자가 있던 자리는 확실히 말풍선 안이다.
- `render.bubble_fit`(기본 0.7): 완전 내접(1)은 글자가 말풍선을 절대 안 벗어나지만 상자가 좁아 글자도 작아진다. 0은 본체 사각형 그대로라 모서리로 크게 삐져나온다. 121장 기준 1 → 0.7로 낮추면 24px 미만으로 작아진 글자가 52개에서 35개로 줄고, 말풍선 밖으로 나간 글자 픽셀은 1.49% → 1.53%로 거의 그대로다.
- 말풍선 내부를 찾는 flood fill은 **말풍선 박스를 6%만 넘는 범위로 잘라서** 돌린다. 페이지 전체를 대상으로 하면 맞붙은 말풍선끼리 한 덩어리로 번져(257×368 말풍선이 447×761로) 내부 판정이 실패한다. 이 제한으로 본체 측정 성공률이 66% → 99%가 됐다.
- 말풍선 안 글자는 상자가 이웃과 겹쳐도 **서로 밀어내지 않는다**. 각자의 말풍선 안에 들어가므로 글자는 겹치지 않고, 밀면 오히려 한쪽으로 쏠린다. 그림 위 글자끼리, 또는 그림 위 글자와 말풍선 사이의 겹침만 푼다.
- 상자가 겹치는 말풍선 안 글자는 **자리를 나눈다**. 위아래로 나눌 때는 겹치는 구간만 나누고(전체 높이를 균등 분할하면 글자가 바닥으로 몰린다), 두 번역문의 글자 크기가 최대한 같아지는 곳에서 자른다. 좌우로 나란한 갈래(합쳐진 구름 말풍선)는 두 원문 사이에서 좌우로 나눠 각자 자기 갈래에 남긴다. 상자가 살짝만 스쳐도 좌우로 나란하면 자른다 — 번역문이 자리 폭을 꽉 채우면 26px 겹침만으로도 글자가 서로 덮는다.
- 탐지기가 한 갈래 상자에 옆 갈래의 첫 열까지 담으면 그 열이 양쪽에 읽힌다. 앞 영역 끝과 뒤 영역 첫머리가 같으면 앞에서 지운다(상자는 줄이지 않는다 — 줄이면 그 자리의 다른 열이 지우기에서 빠진다).
- 말풍선 밖 세로 글은 열마다 따로 탐지되기도 한다. 윗줄이 맞고 맞닿은 열은 한 영역으로 합친다. 색으로 나눈 조각 중 멀쩡한 조각들 사이에 끼인 가짜 조각(흰 외곽선 때문에 생긴다)은 버리고 다시 합친다.

## 글자 크기 고르기

- `match_size`: 원문 글자 크기를 되짚어 기준 크기로 쓴다. 끄면 `font_ratio × 페이지 높이`. 판형이 다른 작품(가로형 1920×1080 등)에서 글자가 절반 크기로 그려지던 문제를 없앤다. `src_font_scale`(0.79)로 전체를 키우거나 줄인다.
- 원문 크기가 비슷한 것끼리 번역문 크기를 맞춘다. 원문은 한 페이지 대사가 거의 같은 크기인데 번역문은 글 양과 말풍선 모양에 따라 21~34px로 제각각이 된다. 가장 작게 들어간 크기를 묶음의 상한으로 삼되, 기준 크기의 일정 배 밑으로는 내리지 않는다: 말풍선 대사 `bubble_group_floor`(0.8), 말풍선 밖 세로 글 `free_group_floor`(0.7), 겹친 말풍선 묶음 `group_floor`(0.85). 크게 쓴 외침은 원문 크기가 달라 다른 묶음이 되므로 그대로 크게 남는다.
- 줄바꿈: 띄어쓰기 단위 → 안 들어가면 조사·'하-' 용언 앞뒤(마마한테 | 배설 | 하는 거)에서 끊음 → 그래도 안 되면 최소 크기에서만 글자 단위. 목록은 `skaldi/textfit.py` 의 `_PARTICLES`, `_VERB_HEADS`.
- `overflow` 플래그: 최소 크기의 절반까지 줄여도 넘치는 경우. 문장을 줄이는 게 낫다.

## 글꼴·색

- **굵기**는 항상 반영한다. 획 두께와 글자 크기의 비율(`bold_stroke_ratio` 0.19)을 픽셀에서 재서 굵으면 EB, 아니면 B를 쓴다. 다만 한 페이지 대사는 대개 같은 글꼴이므로 페이지 중앙값으로 통일하고, 중앙값에서 크게 벗어난 것(1.5배 이상 굵거나 0.5배 이하로 가는 것)만 자기 측정값을 따른다.
- `match_style`: 글자 크롭 몽타주를 비전 모델에 보내 계열(gothic/mincho/hand)을 판정한다. 실패는 "거의 전부를 손글씨로 답하는" 형태로 나타나므로, 영역이 4개 이상인데 70%를 넘게 손글씨로 보면 판정을 버리고 고딕으로 둔다.
- `match_color`: 원문 획 색을 픽셀에서 재서 쓰되 **유채색으로 측정됐을 때만** 적용한다. 흑백 페이지에서는 안티앨리어싱과 흰 외곽선 때문에 획 색이 회색으로 흔들려, 배경 밝기로 정하는 규칙(밝으면 검정 / 어두우면 흰색 / 중간 회색이면 검정+흰 외곽선)이 더 안정적이다.
- 폰트에 없는 글자는 `fonts.fallback`(나눔스퀘어라운드 B)이 대신 그린다. 손글씨 폰트에는 ♥ ♡ 〜 … 자형이 없어 빈칸으로 그려지며 글줄이 밀린다.
- `fake_bold_ratio`(0.025): 굵은 자형이 없는 손글씨 폰트에서 같은 색 테두리를 덧대 두껍게 만든다. 0.05는 획이 뭉개진다.
- 기본 매핑: 고딕 → 나눔스퀘어라운드 B/EB, 명조 → 나눔명조 R/B, 손글씨 → 나눔펜(붓 서체는 한글이 뭉개져 뺐다). 모두 OFL 무료 폰트로 `fonts/` 에 들어 있다. 손글씨는 같은 크기에서 작아 보여 `font_scale` 로 1.42배 키운다.

## 앞장 건너뛰기

표지·속표지는 번역하지 않고 원본을 둔다(`frontmatter.skip`). 판정 기준은 앞에서 `max_pages`(4)장까지, 말풍선 안 글자가 `max_bubble_text`(1)개 이하이면서 큰 제목 로고(`logo_area`)·컬러(`sat_margin`)·다른 판형(`ratio_margin`) 중 하나에 걸리는 장이다. `frontmatter.analyze: true` 면 앞장도 분석해 JSON에는 남긴다(표지를 직접 식자할 때 쓴다). `--no-skip-front` 로 끄고, `--files` 로 장을 직접 고르면 자동으로 꺼진다.

## GUI 진행 표시

진행도는 자식 프로세스가 `SKALDI_PROGRESS=1` 일 때만 stdout에 찍는 `@@PROG {json}` 한 줄(`skaldi/progress.py`)로 전달된다. GUI는 이 줄을 로그에서 걸러 내고 막대에만 쓴다. CLI로 직접 돌릴 때는 아무것도 찍히지 않는다.

파일 대화상자는 앱 시작 때 미리 띄워 둔 전용 프로세스가 담당한다. gradio 콜백은 작업 스레드라 tkinter를 직접 못 부르고, 클릭마다 새 프로세스를 띄우면 매번 0.43초가 기동에 쓰여 연속 클릭이 밀린다.
