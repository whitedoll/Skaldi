# manga-transimage

일본어 만화 페이지 이미지를 한국어로 완전 식자한 이미지로 바꾸는 개인용 CLI 도구.

## 파이프라인

1. **탐지** `ogkalu/comic-text-and-bubble-detector` (RT-DETR-v2): 말풍선 / 말풍선 안 글자 / 말풍선 밖 글자
2. **OCR** `genshiai-daichi/baberu-ocr` (기본) 또는 LLM 비전 (`--ocr llm`)
3. **순서·분류** 비전 모델(Ollama)이 번호 붙은 페이지를 보고 읽기 순서와 말풍선 밖 글자의 종류(대사/나레이션/라벨/효과음)를 판정
4. **번역** 페이지 단위로 텍스트 모델(Ollama)에 한 번에. 용어집(`glossary.yaml`) 병합. 거부·순화 감지 시 재시도 모델로 자동 전환
5. **지우기** 말풍선 박스 전체를 크롭해 글자 획 픽셀만 찾고(배경 밝기는 글자 상자 안쪽 가장자리에서 측정. 사선·들쭉날쭉한 말풍선이라 그 띠의 밝기가 두 가지 이상 섞이면 국소 배경과 비교하고 LaMa로 메운다), 글자에 인접한 배경 연결 영역 안의 글자만 주변 배경색(정규화 블러 추정)으로 메움 → 말풍선 테두리는 어두워서 배경 영역에 끼지 못하므로 절대 지워지지 않고, 회색 배경·톤도 보존. 그림 위 글자는 LaMa 인페인팅. 좁은 말풍선을 가로로 넓혀 테두리를 다시 그리는 기능도 있으나 **기본은 꺼져 있다**(`erase.widen_bubbles: false`) — 원본 말풍선을 건드리는 것보다 글자가 곡선에 조금 걸치는 편이 낫기 때문
6. **렌더링** `pillow`(기본) / `anytext` / `qwen`(ComfyUI) / `both`(전부 + 비교 이미지)

## 설치

```bash
uv sync --extra gemini --extra anytext
python scripts/download_models.py --anytext   # 모델·폰트 미리 받기 (선택)
```

Ollama가 실행 중이어야 하고 `config.yaml`의 모델(`gemma4:12b` 등)이 받아져 있어야 한다.
Qwen 렌더러는 `scripts/install_comfyui.py`로 ComfyUI를 설치한 뒤 사용한다 (약 25GB).

## 사용

```bash
uv run python translate.py samples                   # 기본 렌더러
uv run python translate.py samples --render both     # 세 렌더러 + output/compare/
uv run python translate.py samples --rerender        # JSON만 읽어 다시 그림 (모델 실행 없음)
uv run python translate.py samples --force           # JSON이 있어도 다시 분석
uv run python translate.py samples --files 08.webp   # 특정 파일만
uv run python translate.py "book.zip"                # zip/cbz → output/book_ko.zip (--export 로 렌더러 선택)
uv run python translate.py samples --out-root D:/결과 # 저장 폴더 지정 → D:/결과/samples_ko/
uv run python translate.py samples --out D:/결과/여기 # 그 폴더에 바로 (이름 접미사 없음, 입력 1개 전용)
uv run python translate.py samples --zip              # 폴더 입력도 결과를 zip 으로 (zip 입력은 원래부터 zip)
uv run python translate.py "output/book_ko" --export-only --zip   # 이미 처리된 것에서 결과만 다시 뽑기
uv run python translate.py a.zip b.zip samples        # 여러 개를 한 번에 (모델은 한 번만 로드)
uv run python bench_models.py samples                # 로컬 모델 비교 → output/bench/report.md
uv run python gui.py                                 # GUI (실행 탭 + 검수 탭), http://127.0.0.1:7860
```

## GUI

`uv run python gui.py`. 포트 7860이 사용 중이면 비어 있는 다음 포트를 자동으로 골라 열고 그 번호를 알려준다 (`--port` 로 직접 지정 가능).

**실행 탭**: 입력은 **한 줄에 하나씩 여러 개**를 넣을 수 있고 목록 순서대로 처리한다.

- **📦 zip/파일 선택**: 파일 대화상자에서 Ctrl·Shift 로 zip/cbz 를 여러 개 한 번에 고른다.
- **📁 폴더 선택**: 폴더 대화상자는 여러 개를 동시에 고를 수 없어서, 취소를 누를 때까지 반복해서 물어본다. 고른 폴더가 차례로 쌓인다.
- 고른 결과는 현재 목록 **뒤에 덧붙고**, 이미 있는 경로는 건너뛴다. **🗑 목록 비우기**로 초기화한다.
- 대화상자는 앱 시작 때 미리 띄워 둔 전용 프로세스가 담당해 클릭하면 바로 열린다(클릭마다 새 프로세스를 띄우면 매번 0.4초가 기동에 쓰이고 연속 클릭이 밀린다). 이미 열려 있는데 또 누르면 새로 열지 않고 안내만 띄운다.
- 이미지를 고르면 그 이미지가 든 폴더를 입력으로 잡는다 (파이프라인 입력 단위가 폴더·압축이라서).
- 다른 기기에서 접속했다면 "브라우저에서 올리기"를 펼쳐 zip 여러 개나 이미지 여러 장을 올리면 `input/` 으로 복사한 뒤 목록에 넣는다.

**저장 폴더**를 지정할 수 있다. 입력마다 그 안에 `<이름>_ko` 폴더가 생긴다. 비우면 `config.yaml` 의 `paths.output`(기본 `output/`)을 쓴다. 여기서 바꾸면 **검수 탭도 같은 폴더를 본다**(목록 새로고침을 누르면 현재 폴더가 표시된다).

**내보내기 탭**에서는 이미 처리된 작업에서 **렌더 결과만** 뽑아낸다. 작업 폴더에는 중간 산출물(`json/` 원문·번역, `clean/` 글자 지운 판, `src/` 압축 푼 원본)이 함께 있는데, 남에게 주거나 뷰어로 볼 때는 결과 이미지만 필요하다. zip 하나로 묶거나 폴더로 복사할 수 있고, 내보낼 위치를 따로 지정할 수 있다. zip 입력으로 만든 작업은 **원본 압축의 항목 이름과 순서를 그대로** 쓰고, 렌더 결과가 없는 항목(이미지가 아닌 파일, 건너뛴 페이지)은 원본을 넣어 구조를 맞춘다.

**설정 파일**은 드롭다운에서 고른다. 루트의 `config*.yaml` 을 모두 읽어 오므로, 작품마다 식자 설정을 따로 두고 골라 쓸 수 있다(예: `config_kamaboko.yaml` — 얇은 본고딕·외곽선 없음). `config.yaml` 이 아닌 것을 고르면 `--config` 로 전달된다. 파일을 새로 추가했다면 GUI 를 다시 띄워야 목록에 나온다.

실행하면 목록 전체를 자식 프로세스 **하나**로 처리한다(입력마다 프로세스를 새로 띄우면 탐지·OCR 모델을 매번 다시 올려야 한다). 로그 위에 진행 막대 두 개가 실시간으로 뜬다.

- **전체 진행**: 몇 번째 작업인지 · 전체 퍼센트 · 경과 시간 · 남은 시간 추정
- **현재 작업**: 작업 이름 · 몇 장 중 몇 장째 · 퍼센트 · 지금 도는 단계(탐지 / OCR / 순서·분류 / 번역 / 지우기 / 렌더링 / 압축 풀기 / zip 만들기) · 한 장이라도 끝나면 **장당 평균 시간**과 이 작업의 남은 시간
- 막대 아래에 **처리 중: `<파일명>`** 이 따로 표시된다

진행도는 자식 프로세스가 `MANGATRANS_PROGRESS=1` 일 때만 stdout 에 찍는 `@@PROG {json}` 한 줄(`mangatrans/progress.py`)로 전달된다. GUI 는 이 줄을 로그에서 걸러 내고 막대에만 쓴다. CLI 로 직접 돌릴 때는 환경변수가 없으니 아무것도 찍히지 않는다.

**검수 탭**: 페이지를 고르면 원본·결과를 나란히 보여주고, 표에서 `text_ko`·`category`·`render`·`style`·`weight`를 고친 뒤 "저장 후 다시 그리기"를 누르면 JSON을 저장하고 그 페이지만 다시 그린다.

## 글꼴·색 맞추기 (config.yaml `render`)

- `match_color`: 원문 획 색을 픽셀에서 측정해 쓴다. 단 **유채색으로 측정됐을 때만** 적용하고, 흑백 글자는 배경 밝기로 정하는 규칙(검정 / 흰색 / 검정+흰 외곽선)을 따른다. 흑백 페이지에서는 안티앨리어싱과 흰 외곽선 때문에 획 색이 회색으로 흔들려 측정값이 오히려 나쁘기 때문이다. 외곽선 색도 순백·순흑이나 유채색일 때만 인정한다.
- **글자 상자는 말풍선 안쪽을 픽셀에서 잰다.** 탐지기가 준 말풍선 박스는 꼬리·뿔까지 감싼 바깥 상자라, 그 중심에 글자를 놓으면 본체에서 한쪽으로 치우친다(폭발형 말풍선에서 40px 넘게 어긋난 예). 그래서 ① 내부 마스크에서 폭이 최대의 40%도 안 되는 가장자리 줄을 잘라 뿔·꼬리를 뺀 **본체**를 구하고, ② 그 안에서 세로 중앙을 유지한 채 실제로 **내접하는 사각형**을 찾아 `body_box`에 넣는다. 둘째 단계가 필요한 이유는 말풍선이 둥근데 글자 상자는 사각형이어서다. 폭 84%·높이 84% 상자는 타원 조건 `(w/W)² + (h/H)² ≤ 1` 을 크게 어겨(0.71+0.71=1.41) 첫 줄과 마지막 줄 양 끝이 말풍선을 뚫고 나간다. 고를 때 넓이가 아니라 '두 변 중 더 많이 깎인 쪽'을 최대화하는데, 넓이로 고르면 납작한 말풍선(채팅 버블)에서 폭을 다 쓰는 대신 높이를 절반까지 깎아 버리기 때문이다. 띠의 좌우 경계는 최댓값·최솟값이 아니라 **85/15 퍼센타일**로 잡는다 — 말풍선에 인물이나 집중선이 걸쳐 한 줄만 안쪽으로 파여도 max/min 을 쓰면 상자 전체가 그만큼 좁아져(584px 말풍선의 왼쪽 153px 손실) 글자가 반대쪽으로 쏠린다.
- `render.bubble_fit`(기본 0.7): 완전 내접(1)은 글자가 말풍선을 절대 안 벗어나지만 상자가 좁아 글자도 작아진다. 0 은 본체 사각형 그대로라 모서리가 크게 삐져나온다. 그 사이를 섞는 값이며, 0.7 이면 글자가 곡선에 살짝 걸치는 대신 크기를 지킨다. 121장 기준 1 → 0.7 로 낮추면 24px 미만으로 작아진 글자가 52개에서 35개로 줄고, 말풍선 밖으로 나간 글자 픽셀은 1.49% → 1.53% 로 거의 그대로다.
- 말풍선 내부를 찾는 flood fill 은 **말풍선 박스를 6%만 넘는 범위로 잘라서** 돌린다. 페이지 전체를 대상으로 하면 말풍선 둘이 맞붙어 있거나 테두리가 열린 곳에서 옆 말풍선·칸 배경까지 한 덩어리로 번져(실측: 257×368 말풍선이 447×761 로) 내부 판정이 통째로 실패한다. 이 제한으로 본체 측정 성공률이 66% → 99% 로 올랐다.
- 말풍선 안 글자는 상자가 이웃과 겹쳐도 **서로 밀어내지 않는다**. 각자의 말풍선 안에 들어가므로 글자는 겹치지 않는데, 밀면 상자 중심이 말풍선 중심에서 벗어나 글자가 한쪽으로 쏠린다(맞붙은 말풍선에서 양옆으로 벌어지던 원인). 그림 위 글자끼리, 또는 그림 위 글자와 말풍선 사이의 겹침만 푼다.
- 상자가 겹치는 말풍선 안 글자는 **세로로 나눠 갖는다**. 원문이 세로쓰기면 한 말풍선 안의 줄마다 다른 영역으로 탐지되곤 하는데(구름 말풍선 하나에 '준짱' / '오랜만이야' / '다시 만나서 기뻐'), 그대로 두면 모두 같은 상자를 받아 글자가 같은 자리에 겹쳐 그려진다. 가로쓰기로 옮기면 위→아래가 자연스럽다. 나누는 것은 **겹치는 구간뿐**이다 — 그룹 전체 높이를 균등 분할하면 원래 겹치지도 않던 부분까지 잘려 글자가 말풍선 바닥으로 몰린다. 또 **세로로 나란히 겹칠 때만**(세로 겹침이 상자 높이의 50% 이상) 나눈다. 대각선으로 인접한 두 말풍선은 사각형 상자의 모서리만 스치므로 나누면 안 된다.
- 글자 배치 상자는 페이지 단위로 서로 겹치지 않게 정한다. 말풍선 밖 세로 글자를 가로쓰기로 바꾸려면 상자를 옆으로 넓혀야 하는데, 이웃 글자와 페이지 경계까지 남은 공간만큼만 넓히고 이웃도 넓어질 영역이면 사이 공간을 반씩 나눈다. 탐지 상자끼리 이미 겹쳐 있던 경우는 서로 반씩 물러난다.
- **굵기**는 항상 반영한다. 획 두께와 글자 크기의 비율(`bold_stroke_ratio`)을 픽셀에서 재서 굵으면 나눔스퀘어라운드 EB, 아니면 B를 쓴다. 픽셀 측정이라 믿을 만하다.
- `match_style`: 글자 크롭 몽타주를 비전 모델에 보내 계열(gothic/mincho/hand)을 판정한다. 실패는 "거의 전부를 손글씨로 답하는" 형태로 나타나므로, 영역이 4개 이상인데 70%를 넘게 손글씨로 보면 판정을 버리고 고딕으로 두고 JSON 경고에 남긴다. 만화 대사는 대부분 인쇄체라서 이 규칙이 잘 듣는다.
- 폰트에 없는 글자는 대체 폰트로 이어 그린다. 손글씨 폰트에는 ♥ ♡ 〜 … 자형이 없어서, 없으면 빈칸으로 그려지며 자리만 차지해 글줄이 한쪽으로 밀린다. `fonts.fallback`(기본 나눔스퀘어라운드 B)이 그 글자만 대신 그린다.
- `fake_bold_ratio`: 굵은 자형이 없는 폰트(손글씨)에서 같은 색 테두리를 덧대 두껍게 만든다. 0.05는 획이 뭉개져 0.025가 적당하다.
- 기본 매핑: 고딕 → 나눔스퀘어라운드 B/EB, 명조 → 나눔명조 R/B, 손글씨 → 나눔펜(붓 서체는 한글이 뭉개져 뺐다). 모두 OFL 무료 폰트로 `fonts/`에 있음.

## 출력

결과만 따로 빼내려면 GUI 의 내보내기 탭이나 `--export-only` 를 쓴다(`mangatrans/export.py`). 입력마다 전용 폴더가 생긴다. 이름은 `<입력 이름><접미사>` 이고 접미사는 `config.yaml` 의 `paths.output_suffix`(기본 `_ko`)로 바꾼다. zip 입력은 결과 zip도 같은 이름으로 나온다. 이미지가 아닌 항목은 그대로 복사된다.

```
output/
  samples_ko/                     ← 폴더 입력 (samples/)
    json/<이름>.json              좌표·원문·번역·분류·플래그 (여기를 고치고 --rerender)
    clean/<이름>.png              원문을 지운 이미지
    pillow/<이름>.<확장자>
    anytext/…  qwen/…
    compare/<이름>.jpg            원본 · pillow · anytext · qwen 가로 비교
  book_ko/                        ← zip 입력 (book.zip)
    src/                          압축을 푼 원본
    json/  clean/  pillow/ …
  book_ko.zip                     ← 결과 zip (원본과 이름이 겹치지 않는다)
```

JSON 플래그: `overflow`(최소 크기의 절반까지 줄여도 넘침 → 문장을 줄일 것. 기준 최소 크기에서 안 들어가면 글자 단위 줄바꿈을 허용하고 그 절반까지 더 줄여서라도 말풍선 안에 넣는다 — 글자가 조금 작아지는 편이 밖으로 크게 삐져나오는 것보다 낫다), `refused`(모든 모델이 거부 → 수동 입력), `render`(그릴지), `category`, `text_color`(어두운 말풍선이면 white), `vertical`(세로쓰기로 그렸는지).

## 렌더링 옵션 (config.yaml `render`)

- `font_ratio` / `min_font_ratio`: 기준·최소 폰트 크기(페이지 높이 대비). 단어 중간 끊기는 최소 크기에서도 안 들어갈 때만 허용
- `vertical_for_narrow: true`: 높이/폭이 `narrow_ratio` 이상인 좁고 긴 말풍선은 세로쓰기
- 배경 밝기에 따라 글자색 자동: 밝음 → 검정, 어두움 → 흰색, 중간 회색 → 검정 + 흰 외곽선(제목 상자 관례)
- 외곽선 두께: 그림 위 글자는 `stroke_ratio`(0.12), 말풍선 안 글자는 `bubble_stroke_ratio`(0.05). 원문도 대개 얇은 흰 테두리를 두르고 있어 말풍선 안에도 넣는다. 0으로 두면 외곽선 없음
- `erase.widen_bubbles`(기본 `false`): 켜면 좁은 말풍선을 넓힌다. 지금 상자에 기준 크기의 `widen_min_font_ratio` 이상으로 `widen_max_lines` 줄 안에 들어가면 손대지 않음. 그 밖의 말풍선만 가로로 확대하고 원본 테두리 두께로 다시 그림. 최대 확장은 `widen_max_ratio`. 넓힌 만큼 주변 그림이 가려진다. 확대는 마스크가 아니라 **윤곽선(점 목록)** 에 적용한다 — 마스크를 픽셀째 늘리면 계단이 남아 말풍선이 다각형처럼 각져 보이고, 흐림·이진화로 계단을 지우면 이번엔 가는 부분이 사라져 옛 윤곽선만 남아 테두리가 두 겹이 된다. 뿔이 뻗은 폭발형 말풍선은 아예 넓히지 않는다(늘이면 뿔이 뭉개져 원래 모양을 잃는다)
- 효과음 예외: 같은 글자 반복(おおおお), 말풍선 밖 짧은 가타카나 소리(ゴキュッ)는 규칙으로 확정. 말풍선 안 글자는 비전 모델과 번역 모델이 둘 다 sfx라고 해야 효과음으로 보고 원본을 유지(JSON에 음역만 기록). 같은 말풍선에 확정 효과음이 있으면 함께 잡힌 짧은 조각도 효과음. 웃음·콧소리(クスクス, フフ)와 히라가나 감탄사(そう, へぇ〜)는 항상 대사로 번역
- 줄바꿈: 띄어쓰기 단위 → 안 들어가면 조사·'하-' 용언 앞뒤(마마한테 | 배설 | 하는 거)에서 끊음 → 그래도 안 되면 최소 크기에서만 글자 단위. 목록은 `mangatrans/textfit.py`의 `_PARTICLES`, `_VERB_HEADS`
- 번역 모델이 뜻을 못 잡은 원문(`note: unclear`)은 `needs_review: true`로 표시하고 원본을 유지
- 그림 위 글자(나레이션)는 LaMa로 지우고 흰 외곽선 글자로 그린다

## 주의

- Gemini 백엔드(`--backend gemini`)는 번역 전용 옵션이다. 무료 등급은 입력이 구글 제품 개선에 쓰이고 성인물 입력은 약관 위반이다.
- 생성 렌더러(AnyText, Qwen)는 글자 정확도가 Pillow보다 낮다. 비교 용도로 둔다.
- Qwen 렌더러 속도(RTX 3080 Ti 12GB): `qwen.crop_size` 768 기준 말풍선당 약 1분, 1024는 약 8분(VRAM 오프로드 급증). 첫 실행 시 ComfyUI 기동·모델 적재에 2~3분 추가.
- ComfyUI는 `qwen.autostart: true`면 파이프라인이 자식 프로세스로 띄우고 끝나면 내린다. 이미 떠 있으면 그것을 쓴다.
- `config.yaml`의 `qwen.clip_device: cpu`는 텍스트 인코더(7.9GB)를 RAM에 두어 확산 모델이 VRAM을 더 쓰게 한다.
